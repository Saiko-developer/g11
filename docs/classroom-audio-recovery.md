# Classroom audio startup and recovery

- Teaching setup is embedded in **Admin dashboard → Teaching setup** (`/admin?panel=teaching`). `/teaching-setup` redirects there. Existing admin authentication and API role checks remain in place. The dashboard has a navigation button and overview shortcut.
- Removed the student-facing cache-reuse sentence from the preparation indicator.
- A teaching block starts after a **contiguous first half** of its remaining clips is prepared (8/16 for a fresh sixteen-step block). Two warm workers continue the remainder while playback runs. Moving to the next clip waits only for that clip, rather than another half-block. Browser downloads stay in the existing small rolling window and do not race generation workers for unprepared clips.
- Pause stops warm workers and late playback. Resume keeps completed preparation and restarts background warming. Progress reflects ready clips, never requests merely scheduled or pending.

## Confirmed stuck clip

Read-only hosted inspection found exactly 15 ready clips and one old `preparing` clip for Grade 10 Unit 1 Grammar (`rule-first-v1`). The preparing row had no uploaded storage object. The old claim had no expiry/recovery mechanism, and direct Gemini speech had no deadline.

Migration `0011_recover_classroom_audio_leases` adds a generation token, a 150-second ownership lease, and a bounded crash-recovery attempt counter to the existing private table. Historical preparing leases are backdated from their creation time, so abandoned claims become recoverable immediately. The new service-only claim RPC acquires missing clips or expired preparing claims atomically. A live claim and a ready clip cannot be stolen. Ready/failed writes are fenced by hash, token and state, so an interrupted old worker cannot overwrite a recovery worker.

Gateway plus direct-Gemini classroom narration now has a total 100-second deadline, also passed to the direct fallback. A deadline leaves a recoverable expired claim; other provider failures require review. Repeated worker crashes have a bounded recovery budget to prevent a paid retry loop; this is not a daily lesson/clip quota. If a worker uploaded a valid canonical file before being interrupted, recovery restores it without paid generation. Ready audio is retained. This update does not change default self-study TTS behavior or textbook material.

## Verification

Unit/component tests cover half-ready startup with the sixteenth clip held pending, contiguous readiness, two-worker concurrency, background failure, pause/resume, unchanged ready clips, fenced updates, expired lease recovery, uploaded-file restoration, deadline propagation and the admin teaching panel. `scripts/verify-classroom-audio-leases.mjs` checks actual migrations in disposable PostgreSQL, including service-only permissions and recovery bounds. Production build, TypeScript, focused ESLint and browser guest/redirect checks supplement these tests.

No live paid narration is generated by development tests. The existing abandoned row is made reclaimable by the migration; its actual audio is regenerated on the next authenticated classroom request after the new server code syncs.
